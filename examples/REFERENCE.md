# Jernerics Examples: Agent Reference

Guide for implementing and testing jernerics example projects.

## Setup & Workflow

### Always `cd` into the example directory first

`jernerics` reads `pyproject.toml` from CWD. Running from the repo root reads the root pyproject.toml which has placeholder HPC config and will fail.

### Local dev vs container builds

`pyproject.toml` `[tool.uv.sources.jernerics]` must be a **git source** for container builds — local path sources don't exist inside the container. For local dev against uncommitted changes, temporarily switch to `path = "../.."`, then switch back before building.

```toml
# For container builds (production):
[tool.uv.sources.jernerics]
git = "https://github.com/jerrydzhang/jernerics.git"
branch = "optuna-mlflow-integration"

# For local dev (temporary):
[tool.uv.sources.jernerics]
path = "../.."
```

After switching back to git source, run `uv lock --upgrade-package jernerics && uv sync` to update the pinned commit hash.

### Testing order

1. **Local run**: `jernerics run local dag.py config.py`
2. **SLURM dry-run**: `jernerics run slurm dag.py config.py --dry-run`
3. **Container build**: `jernerics container build --force`
4. **Real SLURM submission**: `jernerics run slurm dag.py config.py`

### After changing jernerics source

1. Commit + push to the git branch
2. In the example dir: `uv lock --upgrade-package jernerics && uv sync`
3. Rebuild container: `jernerics container build --force` (container has jernerics installed inside)
4. Resubmit

## Container Builds

### /dev/shm sandbox

Container builds use `/dev/shm` (node RAM) for the Apptainer sandbox. This was fixed because `/scratch` (wekafs network filesystem) was catastrophically slow for metadata-heavy small-file operations — 60+ min vs 2-3 min on local storage. The build script has a `trap` that cleans up on exit.

Allocate enough `mem` in the container config to hold the sandbox (~2-6GB depending on dependencies).

### Container def files

The default Python template includes `README.md` in `%files`. If the project doesn't have one, the build fails with "cannot stat 'README.md'". Always create a minimal README or use a custom def without it.

### Build commands

```bash
jernerics container build --force          # Force rebuild
jernerics logs <build_job_id> --follow     # Follow build progress
```

## SLURM Sweep Architecture

### Generated sweep script

The sweep script is generated by `_generate_sweep_script()` in `src/jernerics/cli.py`. It's a bash script with inline Python that runs inside an Apptainer container via `apptainer exec`.

### Optuna coordination

Optuna uses a shared SQLite DB at `.jernerics/optuna/{study_name}.db` on the remote. All array workers share this DB via the `/work` bind mount. A `flock`-guarded `optuna.create_study()` call runs before each worker's main execution to prevent schema creation races when multiple workers hit a fresh DB simultaneously.

### MLflow

MLflow is optional and controlled by `[tool.jernerics.mlflow]` in pyproject.toml:

```toml
[tool.jernerics.mlflow]
tracking_uri = "http://your-mlflow-server:5000"  # omit to disable
username = "your-username"
```

**When `tracking_uri` is not set**, the generated sweep script skips all MLflow calls entirely. MLflow's file store is unsuitable for concurrent access (SQLite races on schema creation). Users who want MLflow in distributed sweeps must configure a proper backend.

**When `tracking_uri` is set**, env vars are exported (`MLFLOW_TRACKING_URI`, `MLFLOW_TRACKING_USERNAME`, `MLFLOW_TRACKING_PASSWORD`) and all `mlflow.*` calls execute normally.

The DAG (`src/jernerics/dag/dag.py`) is MLflow-agnostic — it never imports or calls MLflow directly.

### `sampler` in config.py

Must be an actual Optuna sampler instance, not a string. It gets pickled into the config namespace via `runpy.run_path()`:

```python
import optuna
sampler = optuna.samplers.TPESampler(seed=42)
```

## HPC Configuration

Example pyproject.toml:

```toml
[tool.jernerics.hpc]
host = "user@cluster.edu"
remote_dir = "~/projects/my-example"
cache_dir = "/scratch/path/user/jernerics"  # for bind mount cache, NOT container builds

[tool.jernerics.container]
partition = "priority"
mem = "4G"
time = "0:10:00"
cpus = 4
```

`cache_dir` is for bind mount cache directories (`[tool.jernerics.binds]`), not container builds. Container builds use `/dev/shm` regardless.

## Container Runtime

### --fakeroot startup variance

The sweep script uses `apptainer exec --fakeroot`. Fakeroot namespace setup time varies wildly across compute nodes — some start in seconds, some take 5-10+ minutes. This is an infrastructure issue, not fixable in code. `--writable-tmpfs` was tested as an alternative but was even worse (most nodes failed entirely).

For real ML workloads running minutes to hours, the startup variance is negligible. For toy examples, expect some trials to timeout on slow nodes.

### Checking results

```bash
# Per-trial status
ssh user@host 'for i in $(seq 1 20); do echo -n "Trial $i: "; grep -c "DAG completed" ~/projects/example/.jernerics/logs/<job_id>_${i}.out 2>/dev/null || echo "MISSING"; done'

# Optuna DB results (via sqlite3 on remote host)
ssh user@host "cd ~/projects/example && python3 -c '
import sqlite3
conn = sqlite3.connect(\".jernerics/optuna/<db_name>.db\")
trials = conn.execute(\"SELECT state, COUNT(*) as cnt FROM trials GROUP BY state\").fetchall()
for row in trials:
    print(\"state=%s count=%d\" % (row[0], row[1]))
conn.close()
'"
```

## Path Expansion Rules

`~` expansion depends on context:

- **SSH commands**: `~` expands (remote shell processes it)
- **SLURM directives** (`#SBATCH --output`): `~` does NOT expand, use `$HOME`
- **Double-quoted strings in bash scripts**: `~` does NOT expand, use `$HOME`
- **Heredocs**: `~` does NOT expand, use `$HOME`

See AGENTS.md for the full rules.

## Pre-commit Hooks

Pre-commit hooks run ruff check, ruff format, and ty check. Commits will fail if any hook fails.

## Known Issues

- **`tests/integration/test_workflow.py`** uses old `configs = [...]` format not supported by SweepConfig. Pre-existing, don't waste time on it.
- **`load_jernerics_config`** returns 4 values: `(HpcConfig, ShellConfig, BindsConfig, MlflowConfig)`. Any caller unpacking 3 values will fail.
- **`project_name`** is passed to the DAG constructor and derived from `pyproject.toml` project name.
