# Jernerics v2.0 Release Backlog

Code review findings from DAG/Container/SLURM migration. Issues must be resolved before v2.0 release.

---

## Critical (Block Release)

### CR-05: Path traversal in template loading
- **File**: `src/jernerics/container/templates.py:6`
- **Description**: `template_name` is concatenated to form path without validation. Input like `../../etc/passwd` could read arbitrary files.
- **Fix**: Validate `template_name` contains only alphanumeric, underscores, hyphens. Reject path separators or `..`.

## High Priority (Security & Correctness)

### HI-07: Shell injection in SLURM workdir
- **File**: `src/jernerics/hpc/slurm.py:81`
- **Description**: `workdir` is interpolated directly into `cd {workdir}` without `shlex.quote()`. Paths with spaces or shell metacharacters cause injection.
- **Fix**: Use `shlex.quote(workdir)` before interpolation.

### HI-08: Shell injection in CLI logs command
- **File**: `src/jernerics/cli.py:543,549,551`
- **Description**: `log_file` passed to SSH commands without shell escaping. Paths with special characters cause injection.
- **Fix**: Use `shlex.quote(log_file)` before passing to SSH.

### HI-09: Shell injection in CLI clean command
- **File**: `src/jernerics/cli.py:753`
- **Description**: `path` passed to `rm -rf` via SSH without escaping. Malformed paths could delete wrong files.
- **Fix**: Use `shlex.quote(path)` before passing to SSH.

### HI-10: Shell injection in CLI shell command
- **File**: `src/jernerics/cli.py:666-674`
- **Description**: `remote_dir` concatenated into shell command without escaping. Paths with spaces break command.
- **Fix**: Use `shlex.quote()` for `remote_dir` or use `run_script()` method.

### HI-11: Shell injection in container builder
- **File**: `src/jernerics/container/builder.py:56,119-120`
- **Description**: Paths interpolated into bash scripts without shell quoting. `remote_dir` with spaces/metacharacters breaks scripts.
- **Fix**: Use `shlex.quote()` for all paths in shell commands.

### HI-12: SCP paths not escaped
- **File**: `src/jernerics/hpc/sync.py:68,89,101`
- **Description**: Remote paths in scp commands not escaped. Paths with spaces break scp.
- **Fix**: Properly escape remote paths for scp (use `shlex.quote()` or rsync with `--protect-args`).

### HI-13: Exception masking in DAG finally block
- **File**: `src/jernerics/dag/dag.py:103-106`
- **Description**: If `execute_dag()` raises and `provenance.to_json()` also fails in finally, original exception is masked.
- **Fix**: Wrap finally block operations in try/except, log errors, chain exceptions properly.

## Medium Priority (Robustness)

### ME-11: Missing __name__ for callable objects
- **File**: `src/jernerics/dag/task.py:26`
- **Description**: `getattr(fn, "__name__")` raises `AttributeError` for callable class instances without `__name__`.
- **Fix**: Add fallback: `getattr(fn, "__name__", getattr(type(fn), "__name__", "unnamed_task"))`

### ME-12: No error handling in output deserialization
- **File**: `src/jernerics/dag/state.py:32-35`
- **Description**: `_deserialize_output()` has no try/except for cloudpickle import failure, malformed hex, or corrupted data.
- **Fix**: Wrap deserialization in try/except, return raw data or sentinel on failure with warning.

### ME-13: State file inconsistency on partial write
- **File**: `src/jernerics/dag/state.py:123-130`
- **Description**: If main state file writes succeed but `latest_{config_index}.json` fails, system is in inconsistent state.
- **Fix**: Write to temp files first, then atomic rename. Or write latest file first.

### ME-14: Duplicate @dataclass decorator
- **File**: `src/jernerics/hpc/slurm.py:57`
- **Description**: `SlurmJob` class has `@dataclass` decorator applied twice consecutively.
- **Fix**: Remove one of the duplicate decorators.

### ME-15: include_completed parameter is dead code
- **File**: `src/jernerics/hpc/slurm.py:98-101`
- **Description**: `list_jobs(include_completed=...)` has no effect - both branches run identical commands.
- **Fix**: Implement with `sacct` for completed jobs or remove unused parameter.

### ME-16: submit_inline bypasses SSHClient abstraction
- **File**: `src/jernerics/hpc/slurm.py:86`
- **Description**: `submit_inline()` calls `subprocess.run(["ssh", ...])` directly instead of `self.ssh.run()`.
- **Fix**: Refactor to use `self.ssh.run()` with stdin support.

### ME-17: Silent tar extraction failure
- **File**: `src/jernerics/hpc/sync.py:74`
- **Description**: `tar xzf sync.tar.gz || true` silently ignores extraction failures, leaving incomplete sync.
- **Fix**: Check tar exit code and raise exception on failure.

### ME-18: No timeout on run_script
- **File**: `src/jernerics/hpc/ssh.py:29`
- **Description**: `run_script()` has no timeout parameter. Hanging remote scripts block indefinitely.
- **Fix**: Add `timeout` parameter with sensible default.

### ME-19: Unvalidated project_name in remote_dir
- **File**: `src/jernerics/container/builder.py:38-39`
- **Description**: `project_name` from directory name substituted into `remote_dir` without sanitization.
- **Fix**: Validate project_name contains only safe characters or sanitize.

### ME-20: No DAG file existence validation
- **File**: `src/jernerics/cli.py:64`
- **Description**: `dag_file` argument never validated for existence. Fails with confusing error later.
- **Fix**: Add explicit validation: `if not Path(dag_path).exists(): raise FileNotFoundError(...)`

### ME-21: Container path existence not validated
- **File**: `src/jernerics/cli.py:79`
- **Description**: Container path converted to absolute but not validated for existence.
- **Fix**: Add validation for container path existence.

### ME-02: Hardcoded sync file list
- **File**: `src/jernerics/hpc/sync.py:33-39`
- **Description**: Hardcoded file list (`pyproject.toml`, `uv.lock`, `dag.py`, `config.py`, `src/`). Different project structures won't sync properly.
- **Fix**: ~~Make sync list configurable or auto-discover.~~ Added `files` and `dirs` parameters to `sync_project()` with defaults as class constants `DEFAULT_FILES` and `DEFAULT_DIRS`.

### ME-05: Exception traceback lost
- **File**: `src/jernerics/dag/executor.py:102-103`
- **Description**: When catching exceptions from futures, the **original traceback is lost**, making debugging harder.
- **Fix**: ~~Preserve traceback in exception wrapping.~~ Now uses `traceback.format_exception()` to capture full traceback and includes it in the error message stored in state.

### ME-06: Job name parsing breaks on pipe character
- **File**: `src/jernerics/hpc/slurm.py:51-66`
- **Description**: Job parsing assumes exactly 6 pipe-separated fields. Job names containing `|` will **break parsing**.
- **Fix**: ~~Use more robust parsing or escape/encode job names.~~ Changed delimiter from `|` to tab (`\t`) which is less likely to appear in job names.

### ME-07: State dir path assumption
- **File**: `src/jernerics/dag/state.py:149`
- **Description**: `from_json` uses `path.parent.parent` for state_dir, assuming file is in `runs/`. Wrong path if file is elsewhere.
- **Fix**: ~~Store state_dir explicitly or validate path structure.~~ Added `state_dir` to `to_dict()` serialization and `from_json()` reads it back with fallback to `path.parent.parent` for backward compatibility.

### ME-09: Linux-only stat command
- **File**: `src/jernerics/hpc/ssh.py:36-40`
- **Description**: `getmtime` uses `stat -c %Y` which is **Linux-specific**, won't work on BSD/macOS remotes.
- **Fix**: ~~Detect OS or use portable alternative.~~ Changed to `stat -c %Y ... 2>/dev/null || stat -f %m ...` which tries Linux format first, then BSD/macOS format as fallback.

### ME-10: Excessive default thread count
- **File**: `src/jernerics/dag/executor.py:39`
- **Description**: Default `max_workers=None` uses `os.cpu_count() * 5`, potentially creating **excessive threads**.
- **Fix**: ~~Use more conservative default or require explicit setting.~~ Added `_get_default_max_workers()` function that returns `min(8, os.cpu_count() or 4)`.
