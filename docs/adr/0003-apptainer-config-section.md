# Container-runtime-specific config as separate sections

When `container_type = "apptainer"`, container-specific options (currently just `build_dir` — a host-local scratch directory for staging builds) live in a dedicated `[tool.jernerics.backends.<name>.apptainer]` TOML table, parsed into an `ApptainerConfig` dataclass. This mirrors the existing pattern where `type = "slurm"` → `SlurmConfig` and `type = "pueue"` → `PueueConfig`. A generic `build_dir` field on `SharedConfig` was considered but rejected: the "stage somewhere fast, copy back" pattern only applies to Apptainer (Docker images live in the daemon store, not as files). A runtime-specific name on shared config (`apptainer_build_dir`) was also considered but a dedicated section scales better when Docker or other runtimes later need their own options, and it mirrors how Nix structures similar configuration.
